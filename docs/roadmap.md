## 1. 路线图结论

项目从 2026-09-23 开始，到 2027-04-10 答辩约有 28 周。关键路径是：

```text
规范与数据模型
  → 单源最小闭环
  → Agent Core + 证据链
  → 五源 MCP 联邦
  → 评测与消融
  → 论文正文与答辩
```

必须优先保证：

1. 2026-11-29 前完成开题报告和可演示的最小闭环。
2. 2027-01-15 前完成多源、归档、报告和 Web 证据链。
3. 2027-02-28 前完成主要实验和论文初稿。
4. 2027-03-19 17:00 前完成论文定稿。
5. 论文写作从 2026-12 开始持续进行，不能集中到 3 月。

## 2. 时间预算

按阶段分配；Phase 3–4 总人时为 32–47 小时/周，Phase 0–2 评测投入较低。

| 工作流 | 每周小时 | 说明 |
|---|---:|---|
| Agent Core 与证据链 | 8–10 | runtime、planner、executor、evidence、storage |
| MCP 与源站适配 | 6–8 | 每源独立 server、契约测试、限流与重试 |
| 评测与数据 | 12–22 | Phase 3–4；Phase 0–2 为 4–6 小时/周。问题集、baseline、指标、结果分析 |
| 论文写作 | 4 | 正文、图表、实验记录、参考文献 |
| 文档与代码审查 | 2 | 更新规范、ADR、测试和重构 |
| 缓冲 | 2 | 处理源站变化、解析失败和课程冲突 |

如果某周低于当前阶段预算，优先保留：核心闭环、评测、论文记录；可以延后 Web UI 美化、额外源站和 Office 导出。

## 3. 阶段与里程碑

- ADR 基线。

## 5. 每周工作节奏

建议每周固定：

- 1 次规划会：确认本周目标、风险和冻结项。
- 3 次开发块：Agent Core、MCP、存储与证据。
- 1 次评测块：运行问题集并记录失败样本。
- 1 次论文块：写正文、补图、整理引用。
- 1 次复盘：更新路线图、ADR 和下一周计划。

每周必须留下：

- 可运行增量。
- 测试结果。
- 实验或失败记录。
- 论文素材更新。
- 风险和阻塞项。

## 6. 工作流优先级

### P0：不能延后

- 独立 Agent Core。
- 证据链和引用校验。
- 至少 arXiv + OpenAlex 双源闭环。
- 数据模型和可复现存储。
- 正式问题集和 baseline。
- 论文正文与图表。

### P1：支撑主贡献

- Crossref、Semantic Scholar、DBLP。
- 联邦路由、限流、重试和 provenance 合并。
- Web 证据链。
- 消融实验 A1–A4。
- 错误分析。
- 语义相关性过滤：用 LLM 判断候选摘要是否真正回答子问题，替代当前的词重合匹配。
  人工资评 10 题 pilot 时发现，纯关键词检索会把主题相近但不回答问题的论文收进金标
  （例如把芯片设计、语音数据集、生物医学检索论文匹配到多模态检索题）。
  该能力同时作为一项消融条件（有/无语义过滤对证据准确率的影响）。
  截至 2026-09-23 的人工复核，pilot 数据集（10 题 / 24 篇）已逐条核对六项判据：
  两个子问题均有证据、论文年份在声明范围内、引文为完整句子且能回答其子问题。
  复核过程中替换掉的论文（芯片设计、语音数据集、生物医学检索、RLHF 等）即为该能力的
  动机证据。语义过滤落地后应整体重跑这 10 题，并以本次人工结果作为参照标准衡量其准确率，
  而不是再次逐条手改。

### P2：可延后

- A5 provenance 消融。
- Word、PDF、PPT 导出。
- 额外全文源，如 OpenReview、ACL Anthology、CVF。
- 更复杂的 UI 交互。
- 多项目、多用户和远程部署。

### 不做

- 多 Agent 自治。
- 向量数据库。
- 付费墙绕过。
- 大规模模型微调。
- 与主贡献无关的插件市场。

## 7. 风险登记表

| 风险 | 触发信号 | 影响 | 缓解措施 |
|---|---|---|---|
| 范围膨胀 | 同时做 UI、Office、多 Agent、向量库 | 主线延期 | P0/P1/P2 分层，冻结 v1 |
| MCP 工作量过高 | 五源契约不一致、调试时间超预期 | 开题或中期延期 | 先 arXiv + OpenAlex，五源在 11 月内完成 |
| 评测规模过大 | 720 次 Run、人工标注和重跑超预期 | 实验延期 | 30 题、13 周铺开、B0/B1/B2 与 B3/A1–A4 分批、缓存和批量自动化 |
| 源站 API 变化 | 响应字段或限流变化 | 查询失败 | 契约测试、fixture、manifest、适配器隔离 |
| PDF 解析质量差 | 乱码、页序错误、locator 失效 | 证据链受损 | 多 parser 降级、保留原文本、人工校验 |
| 下载受限 | 403、重定向、验证码 | 无法获取全文 | 只做 OA，记录失败原因，增加开放全文源 |
| 评测数据不足 | 自建问题标注慢 | 无法完成消融 | Pilot 10 题先行，正式集冻结 |
| 金标证据质量差 | 自动生成的引文是背景句、论文与子问题不对口 | 评测指标失去意义 | 逐条人工复核（六项判据）、`add_gold_evidence` 前置校验、语义过滤（P1） |
| LLM 成本高 | token 或费用超预算 | 实验无法完成 | 确定性步骤优先，缓存，预算上限 |
| 论文写作滞后 | 2 月仍无方法章 | 定稿风险 | 12 月起每周写正文，里程碑检查 |
| 单点环境故障 | 本机损坏、数据库丢失 | 数据不可恢复 | 定期备份、导出报告和实验记录 |
| 演示失败 | 答辩时网络或 API 不可用 | 影响答辩 | 准备离线数据、录屏和 mock source |

## 10. 路线图维护规则

- 每周更新一次实际进度和风险。
- 里程碑变更必须写明原因、影响和补偿措施。
- 新增功能必须先判断是否影响证据链主贡献。
- 如果进度落后，优先削减 P2，不允许削减测试、评测和论文记录。
- 学校截止日期当天 17:00 前完成提交，内部截止日期提前至少 48 小时。
