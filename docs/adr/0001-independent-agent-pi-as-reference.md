# ADR-0001：独立 Agent，Pi 仅作参考

- 状态：Accepted
- 日期：2026-09-23
- 决策者：LYY
- 关联文档：`docs/PRD.md`, `docs/architecture.md`

## 背景

Pi 是开源 Agent 框架，具有开放的插件、Skills 和 MCP 生态。它可以作为设计参考，但如果直接 fork 后改名为“自研框架”，论文中很难证明核心贡献，也容易被质疑为套壳。

本项目是毕业设计，需要同时满足：

- 有独立可运行的 Agent 系统。
- 核心逻辑由作者实现。
- 有可辩护的论文贡献。
- 能借鉴成熟框架的经验，但不把框架本身当成创新。

## 决策

采用独立 Agent Core，Pi 仅作为架构和交互设计参考：

- 不把 Pi 加入运行时依赖。
- 不直接 fork Pi 后改名。
- 自研 runtime、planner、executor、memory、router、policy、evaluator 和 evidence engine。
- 可以借鉴 Pi 的 Skills、插件发现和 MCP 适配思路。
- 如果使用第三方库，必须说明其边界，不把库能力声称为自研。

## 后果

正面：

- 核心模块和证据链贡献可归因于本项目。
- 可针对科研场景设计数据模型和评测。
- 不绑定 Pi 的版本、接口和升级节奏。
- 论文更容易解释模块边界和实现工作量。

负面：

- 需要自行实现状态管理、工具调用和错误恢复。
- 无法直接复用 Pi 的现成生态。
- 开发时间增加，必须严格限制 v1 范围。

## 备选方案

1. Fork Pi 并修改：开发快，但论文原创性弱，拒绝。
2. 直接使用 Pi 作为运行时：实现快，但核心不可控，拒绝。
3. 完全从零复刻通用 Agent 框架：范围过大，偏离科研证据链，拒绝。

## 约束

- 任何第三方框架都必须处于可替换位置。
- 新增依赖不得绕过 Policy、Evidence 和存储边界。
- 论文中明确区分“借鉴设计”和“作者实现”。
