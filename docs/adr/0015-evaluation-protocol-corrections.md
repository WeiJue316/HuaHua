# ADR-0015：评测口径修正（排序 Top-K、论文身份键、路由预算、单因素 A4）

- 状态：Accepted
- 日期：2026-09-26
- 决策者：LYY
- 关联文档：`docs/evaluation.md`, `docs/roadmap.md`, `docs/adr/0009-evaluation-scale-and-task-metric-separation.md`, `docs/adr/0012-semantic-relevance-filtering.md`

## 背景

2026-09-26 的全仓审阅发现，评测代码与 `docs/evaluation.md` 的指标定义存在系统性偏差。
这些偏差不会让程序报错，但会让 Pilot 数字失真，且在正式 720 次 Run 开始后无法补救：

1. **Precision/Recall 不是 @K。** `retrieval_metrics` 接收无序集合，Precision 除以保留论文数而不是 K；
   没有 nDCG。B3 的指标基于相关性过滤后的保留集合，而不是排序后的前 K 篇。
2. **同一篇论文有多个键。** 相关性过滤使用 `doi:{原始DOI}`，检索使用 `canonical_key`（DOI 小写并去前缀）；
   arXiv 条目使用 `arxiv:<id>`，金标常用 `doi:10.48550/arxiv.<id>`。精确集合相交会漏记命中，
   被过滤的论文也可能仍被计入保留集合。
3. **A3 与 B3 相同。** 评测中 Planner 的 `max_sources` 等于全部可用源站数，B3 本就查询全部五源，
   “去路由器”消融没有差异。
4. **A4 同时改变两个变量。** 引用约束关闭时，综合提示词额外告诉模型可以引用列表外的标签；
   A4 因而同时改变了提示词和后处理，不是单因素消融。
5. **系统间候选规模和成本口径不一致。** B0 取 Top-K，B2 计入全部搜到的论文，B3 是 K×源站数再过滤；
   `source_attempts` 统计源站个数而非请求次数；固定 `model_call_budget=20` 在 K=20 时几乎必然被 B3 超出。

## 决策

### 1. 检索指标按排序列表计算

- 每个系统必须输出一份**有序候选列表**，长度截断为 K。
- `Precision@K`、`Recall@K`、`nDCG@K`（二元相关性）一律在该列表上计算，分母按 `docs/evaluation.md` §6.1。
- 现有集合指标保留，改名为 `precision_kept`、`recall_kept`，只用于诊断相关性过滤，不进入论文主表。
- 正式实验 K=20；Pilot 调试可用更小 K，但必须在结果记录中写明。
- 轮转交错避免“排在前面的源站占满前 K 名”；若要改用相关性重排，必须新建 ADR，
  并作为独立配置报告。

排序规则：

| 系统 | 排序依据 |
|---|---|
| B0 | BM25 得分 |
| B1/B3/A1–A4/A6 | 按源站轮转交错（各源第 1 名，再各源第 2 名……），源内保持源站返回顺序；相关性过滤只删除、不重排 |
| B2 | 论文首次被检索到的顺序 |

### 2. 统一论文身份键

- 新增唯一的身份键函数，运行时、相关性过滤、指标和金标比对全部使用它。
- 同一篇论文的 DOI、arXiv ID、`10.48550/arxiv.<id>` 形式的 arXiv DOI、OpenAlex ID 视为同一身份。
- 检索列表在计算指标前按身份键去重，保留首次出现的位置。

### 3. 路由预算与 A3

- B3 的 Router 在每题最多选择 **3** 个源站，由 Planner 打分决定；其余源站进入 `fallback_sources`。
- A3 固定查询全部五个源站，不经过打分截断。
- B1 仍固定为 OpenAlex 单源。

### 4. A4 为单因素消融

- A4 与 B3 使用完全相同的综合提示词（`synthesis-v1`）。
- 两者唯一区别是后处理：B3 把没有真实 Evidence Span 的 `supported` / `partially_supported` Claim
  降为 `unsupported`；A4 保留模型给出的状态，只丢弃无法写入 `claim_evidence` 的未知 span id。
- A4 相对 B3 的主要可比指标是 `dangling_support_count` 与 `unsupported_claim_rate`。

### 5. 成本与预算口径

- 新增 `source_http_calls`：实际发出的源站请求次数（含查询变体与重试），用于 H2b。
- `source_attempts` 保留为“被调用的源站数”，不再用于 H2b。
- Task Completion 的模型调用预算按系统配置估算（K、源站数、是否启用相关性过滤与综合），
  在正式实验前固定并写入评测配置快照，不再使用固定默认值 20。

## 后果

正面：

- 指标与文档定义一致，B0/B1/B2/B3 可在同一 K 下比较。
- A3、A4 成为真正的单因素消融，RQ2/RQ1 结论可解释。
- 身份键统一后，Recall 不会因标识符写法不同而被低估。

负面：

- 2026-09-25 及之前的 Pilot 对比与消融数字**口径作废**，只保留为工程记录，不得在论文中引用。
- B3 查询源站数下降，单题 Recall 可能下降；这是路由的真实代价，需要与 A3 一起报告。
- 需要重新生成 Pilot 结果，占用约一次 Pilot 全量运行的模型成本。

## 备选方案

1. 维持集合指标、只改文档定义：拒绝，论文指标名与计算方式不符。
2. 从 720 次核心实验中删除 A3：拒绝；用户选择保留 A3 并给 B3 设路由预算。
3. 保留 A4 的额外提示词并改称“提示词 + 约束”消融：拒绝，无法单独回答“引用约束是否有效”。

## 约束

- 本 ADR 的修正必须在 2026-12-01 正式 B0/B1/B2 批次开始前完成并冻结。
- 修正完成后，用冻结快照、K=20 重跑 Pilot 10 题，新结果写入 `evaluation/results/`，并注明本 ADR 编号。
