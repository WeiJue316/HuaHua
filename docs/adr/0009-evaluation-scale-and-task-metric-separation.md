# ADR-0009：正式评测规模与任务指标拆分

- 状态：Accepted
- 日期：2026-09-23
- 决策者：LYY
- 关联文档：`docs/evaluation.md`, `docs/roadmap.md`, `docs/adr/0006-evaluation-driven-development.md`

## 背景

原评测设计允许 30–50 个正式问题、4 个 baseline、4 个消融，并要求每个系统在每个问题上运行 3 次。全量规模会达到 720–1500 次 Run，按原计划 6 周完成不现实。同时，原 Task Success Rate 清单包含多源、证据表和引用校验，会让 B0、B1、B2 按定义失败，导致 RQ3 的 baseline 对比被证据链能力污染。

## 决策

- Pilot 集：10 个问题。
- 正式集：30 个问题，冻结后不再修改。
- 核心配置：B0、B1、B2、B3、A1、A2、A3、A4，共 8 个。
- 每个核心配置在每个正式问题上运行 3 次：`30 × 8 × 3 = 720` 次 Run。
- B1 默认使用 OpenAlex；arXiv 版本为可选补充，不计入核心 720 次。
- A5 为可选扩展，不计入核心 720 次。
- 评测窗口：2026-12-01 至 2027-02-28，共 13 周。
- B0/B1/B2 于 2026-12-01 至 2027-01-15 完成；B3/A1–A4 于 2027-01-16 至 2027-02-28 完成。
- 评测人时按 12–22 小时/周规划；项目总人时按 32–47 小时/周规划。
- 任务指标拆分为：
  - `Task Completion Rate`：baseline-neutral，只看报告/答案、子问题覆盖、异常和预算。
  - `Evidence Compliance Rate`：证据和引用校验，用于 RQ1。
  - `Task Success Rate`：完整系统验收，不用于 H3a 的 baseline 比较。
- 人工复核第一轮覆盖 10% 的引用和证据，第二人复核其中 20%。

## 后果

正面：

- 当前规模可以保留 3 次运行，同时分散到 13 周。
- RQ1、RQ2、RQ3 的指标边界清楚。
- baseline 对比更公平，避免“未实现证据链就必然任务失败”。

负面：

- 需要提前准备问题集、评测脚本和自动化批处理。
- B0/B1/B2 必须尽早冻结，不能等 B3 全部完成后再开始。
- 50 题版本不再作为核心承诺，只能在 30 题稳定后追加。

## 备选方案

1. 保留 30–50 题、6 周、全量 3 次：人时和机器时间风险过高，拒绝。
2. 降到 20 题、1 次运行：统计效力不足，拒绝作为主方案。
3. 只做完整系统、不做 baseline：无法支持论文结论，拒绝。

## 约束

- 正式集冻结后不得根据结果修改问题或 gold evidence。
- 任何新增核心配置都必须更新本 ADR 和 `docs/evaluation.md`。
- 所有 Run 必须保存配置、代码版本、模型版本、源站版本和原始结果。
