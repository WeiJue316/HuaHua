# ADR-0002：状态机 + Plan-and-Execute

- 状态：Accepted
- 日期：2026-09-23
- 决策者：LYY
- 关联文档：`docs/architecture.md`, `docs/PRD.md`

## 背景

科研调研包含查询构造、源站路由、下载、解析、证据抽取、引用校验和报告生成。纯 ReAct 循环灵活，但存在：

- 执行轨迹不稳定。
- 失败后难以恢复。
- 检索、下载和引用校验耦合。
- token 和工具调用成本不可控。
- 难以单独评测规划和执行。

## 决策

Agent Core 采用状态机 + Plan-and-Execute：

- LLM 负责研究问题分解、查询意图、相关性判断、证据抽取和综合生成。
- Runtime 负责 Run 和 Step 状态流转。
- Executor 执行确定性步骤。
- Router、Storage、Evidence 和 Policy 作为独立组件。
- 支持暂停、恢复、重试、取消和重规划。

## 后果

正面：

- 每一步可记录、可恢复、可测试。
- 能单独评测规划器、路由器和证据链。
- 控制 LLM 调用范围和成本。
- 更容易处理源站超时和部分失败。

负面：

- 计划模板和状态机增加实现复杂度。
- 复杂问题可能需要多次重规划。
- 不能像纯 ReAct 那样自由探索。

## 备选方案

1. 纯 ReAct：灵活但不可控，作为 baseline B2。
2. 固定流水线：稳定但无法处理复杂问题，作为消融 A2。
3. 多 Agent 协作：超出 v1 范围，拒绝。

## 约束

- LLM 不得直接修改 Run 状态。
- Step 必须有明确输入、输出、错误和检查点。
- 确定性操作不得为了“更 Agent”而交给 LLM。
