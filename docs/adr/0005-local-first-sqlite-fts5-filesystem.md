# ADR-0005：Local-first、SQLite + FTS5 + 文件系统

- 状态：Accepted
- 日期：2026-09-23
- 决策者：LYY
- 关联文档：`docs/data-model.md`, `docs/architecture.md`

## 背景

科研项目包含元数据、PDF、解析文本、笔记、证据和报告。第一版是单用户、单机、单项目环境，需要可复现、可审计和低成本。引入云数据库或向量数据库会增加部署和数据边界复杂度，且不直接解决证据链问题。

## 决策

采用 local-first 存储：

- SQLite 保存实体、关系、状态、审计和 FTS5 索引。
- 文件系统保存不可变 PDF、解析文本、Markdown 笔记和报告。
- 数据库保存文件路径和 SHA-256，不保存 PDF 二进制。
- 使用 FTS5 做全文检索，v1 不引入向量数据库。
- Zotero、BibTeX、JSON 和 CSV 作为导出视图，不作为主库。
- 云端 LLM 只处理明确允许的文本，并记录数据边界。

## 后果

正面：

- 部署简单，适合单机和毕业设计环境。
- 数据和证据链容易备份、检查和复现。
- 文件哈希可验证 PDF 完整性。
- 后续可迁移到 PostgreSQL 或对象存储。

负面：

- SQLite 不适合高并发多用户。
- FTS5 的语义检索能力弱于向量检索。
- 文件系统和数据库需要保证一致性。
- 大文件和大量源站缓存需要清理策略。

## 备选方案

1. 云数据库 + 对象存储：v1 过度设计，拒绝。
2. 向量数据库：不直接解决引用和 locator，拒绝进入 v1。
3. Zotero 作为主库：外部依赖强，难以表达 Evidence 和 Claim，拒绝。

## 约束

- 文件写入使用临时文件 + 哈希校验 + 原子移动。
- Source Record 不可变。
- 数据库 schema 变更必须写 ADR 和迁移方案，并获得用户确认。
- 删除原始文献必须人工确认。
