## 0. 本文件与项目开发的关系

项目开发计划在 `docs/roadmap.md`，论文计划在本文件，两者互不驱动：

- **开发不看论文**：路线图的里程碑、批次和冻结点按开发需要排期，不因论文节点调整；路线图只在说明分工时指向本文件，不以本文件的日期排期。
- **论文只读项目产物**：论文写作使用已经存在的实验记录、架构文档、ADR 和图表，不直接修改代码、评测配置或路线图。
- **需要新东西时走路线图**：写作中发现需要新实验、新图表或修复，先在 `docs/roadmap.md` §4 登记编号，由开发计划排期；论文计划只记录“等待哪个编号”。
- **材料存放**：论文草稿、开题报告正文、导师反馈、评审记录放在 `local/`，不进 Git（AGENTS.md §5）。本文件只记录计划，不含个人信息。

## 4. 写作节奏（启用时确认）

原始规划如下，启用时按实际启用日期和 §3 的产物状态调整：

| 时间 | 写作内容 |
|---|---|
| 2026-10 | 研究背景、问题定义、相关工作初步调研；开题素材（研究问题、创新点、架构图） |
| 2026-11 | 开题报告、引言和研究方法草案 |
| 2026-12 | 架构、MCP 契约、数据模型章节 |
| 2027-01 | 证据链机制、系统实现和初版实验；中期检查材料 |
| 2027-02 | 正式实验、消融、讨论和结论；初稿完成度至少 80% |
| 2027-03 | 全文整合、格式、查重和定稿 |
| 2027-04 | 答辩 PPT、演示脚本、整改和终版 |
| 2027-05 | 信息核查与存档 |

时间预算：启用后建议每周 4 小时起，Phase 5 之后按需增加。这部分时间不计入路线图 §3 的开发时间预算。

各节点的交付物：

- 开题：开题报告，含研究问题、创新点、架构、计划和初步结果。
- 中期：中期检查材料；方法章和系统实现章初稿。
- 初稿：摘要、引言、相关工作、方法、实现、实验、讨论；至少 8 张核心图表。
- 定稿：图表、公式、参考文献和附录整理；格式检测、查重和整改记录；论文中的数字、图表与实验脚本一致。
- 答辩：评审意见回复、答辩 PPT、Demo 演示脚本和备用录屏。
- 存档：终版论文、信息核查结果、存档材料。
